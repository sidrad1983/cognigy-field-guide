01

How Cognigy is put together

Cognigy is an enterprise platform for building, deploying and managing chat and voice AI Agents, using NLU and LLMs. Learn these nouns first; every later lesson uses them.

Project

Your workspace. Holds Flows, AI Agents, Knowledge Stores, LLM resources, Endpoints and settings.

Flow

A conversation structure made of Nodes. Also carries Intents, Lexicons, Locales and Slot Fillers. Found in Build > Flows.

Node

A building block: Say, Question, If, Lookup, Code, LLM Prompt, AI Agent, and voice Nodes such as Set Session Config.

Input · Context · Profile

The agent's memory: this turn's data (input), session data (context), and the long-lived Contact Profile.

AI Agent & Persona

An LLM-powered agent. The Persona is how it behaves (tone, voice); the Job is what it does in a given Flow.

Endpoint

The channel connector (Webchat v3, Voice Gateway, NiCE CXone, Teams, WhatsApp, REST…). Lives in Deploy > Endpoints.

Interaction Panel

The built-in tester: chat, voice call, live follow and simulation. Opened with Chat with your Agent.

Voice Gateway

Cognigy's telephony layer, with its own Self-Service Portal for carriers, numbers, applications and speech services.

CognigyScript

Template syntax for dynamic values in Node fields, e.g. {{context.hints}} or {{input.text}}.

Get oriented in the UI

  1. Open or create a ProjectFrom the Main page, open a Project. The left-side menu groups everything into Build, Test, Deploy and Manage.
  2. Create a FlowGo to Build > Flows, click + New Flow, give it a Name and Description, then Create.
  3. Add your first NodeIn the Flow editor, click + under the Start Node and add a Say Node with a greeting. Click Save Node.
  4. Test itClick Chat with your Agent (top right) to open the Interaction Panel and type anything to trigger the Flow.
  5. Check the Flow's Settings tabNote the Intent thresholds, Yes/No logic and System Slots (date, email, number…). You will tune these later.
02

Build your first AI Agent

Agentic AI Agents run on an LLM and follow a persona and job instructions instead of a scripted tree. The docs' quickstart uses a parcel-tracking agent; follow along with your own use case.

  1. Add the LLMs firstAdd a language model and an embedding model to the Project (the docs' example: an OpenAI GPT-4o class model plus an embedding model). You need API credentials from the provider. Supported providers include OpenAI, Azure OpenAI, Anthropic, Amazon Bedrock, Google and Mistral.
  2. Create the personaGo to Build > AI Agents. Set the name, description, avatar and speaking style. Optionally assign knowledge and configure security. Click Create.
  3. Assign a jobOn the Jobs tab, set the job title (e.g. Delivery Manager), a description and clear instructions. Cognigy generates a Flow containing an AI Agent Node with this persona.
  4. Add a toolIn Tools, click Add Tool > Regular Tool. Give it a Tool ID such as track_parcel and parameters such as tracking_code. The tool branch in the Flow is where you call your API.
  5. Configure memoryIn Memory Handling, set Long-Term Memory Injection (e.g. Inject full Contact Profile) so the agent can personalise replies.
  6. Look under the bonnetOpen Advanced Editor to see the Nodes behind the agent. This is where you add guardrails, handover and voice settings later.
  7. Deploy to Webchat to testDeploy > Endpoints, add a Webchat v3 Endpoint linked to the Flow, then click Open Demo Webchat.
TipIf an LLM call fails, Cognigy retries automatically (up to three attempts in total). You can also configure an LLM fallback model so the agent keeps working if the main model is down; fallbacks are not supported for embedding models.
03

Ground the agent with Knowledge AI

Knowledge AI is Cognigy's retrieval-augmented generation (RAG) feature: upload documents, and the agent searches them and generates answers from what it finds.

Build > Knowledge
  1. Check prerequisitesKnowledge AI is activated, you have a Project, and you have added an LLM that supports Knowledge Search and Answer Extraction.
  2. Configure StoreOpen Build > Knowledge to start the wizard. Name the store and select the embedding model and its Generative AI Connection. For Azure OpenAI you also need Resource Name, Deployment Name and API Version (YYYY-MM-DD).
  3. Upload KnowledgeCreate your first Knowledge Source by uploading a file. Supported formats include Cognigy CTXT, PDF, web pages and Office documents. Sources are split into searchable Knowledge Chunks.
  4. Configure FlowPick the Answer Extraction model, then click Create Flow. Cognigy builds a test Flow with a Search Extract Output Node.
  5. Test itOpen the generated Flow from Build > Flows, open the Interaction Panel and ask a question your documents answer.
  6. Attach knowledge to your AI AgentBack in the AI Agent's configuration, assign the Knowledge Store so the agent can use it during conversations.
For human agents tooThe same Knowledge Store can feed Agent Copilot through a Copilot: Knowledge Tile Node, and CXone customers can pull from Knowledge Hub with the Retrieve Knowledge Node.
04

Intents and NLU

Intents still matter for deterministic routing, menu choices and voice IVR replacements. Each Intent is a set of example sentences the NLU model learns from.

Flow editor > NLU > Intents
  1. Open the NLU tabOpen your Flow and select NLU in the upper-right corner.
  2. Create an IntentName it for the goal, e.g. OrderFood, and add varied example sentences: Can you get me some food?, I'd like to order a pizza. With an LLM attached you can generate sentences automatically.
  3. Set additional settings if neededDefault Reply, Rules, Conditions, Confirmation Sentence, and the Intent Entrypoint (execute from Start, execute normally, or from a specific Node).
  4. Build the modelClick Build Model (or Quick Build). A red indicator next to the Flow name means it needs rebuilding. To train every Flow, use Train all Flows in Build > Flows.
  5. Tune thresholdsOn the Flow's Settings tab: Intent threshold (0–1), Reconfirmation Threshold (default 0.2) and Confidence Threshold (default 0.4). The last two only matter when the Intent has confirmation sentences.
  6. Route on the resultUse a Lookup Node of type Intent, or an If Node on input.intent, to branch the Flow.
Bulk editIntents import and export as CSV (no header; columns: Intent name, property type such as exampleSentence or defaultReply, value) or as JSON.
05

Where STT and TTS are configured

This is the part most people get wrong. Speech is set in several places, and each layer overrides the one above it for a narrower scope. Click a layer to see what it controls.

Rule of thumbCredentials live in the Voice Gateway Speech Services page. Defaults live on the Application. Anything the conversation needs to change (language switch, different voice, hints) lives in the Flow. Project Voice Preview Settings only drive testing inside Cognigy.

Turn on TTS streaming

Streaming plays audio as soon as the first words are synthesised instead of waiting for the full reply. It's the single biggest latency win for LLM-driven voice agents with long answers.

  1. Edit the speech serviceIn Speech, open the service; make sure Use for text-to-speech is on.
  2. Enable streamingTick Enable text-to-speech streaming. For ElevenLabs you can add Extra Options (not seed, previous_request_ids, next_request_ids, text normalisation, use_pvc_as_ivc or pronunciation dictionaries). Save.
  3. Select it in the FlowIn the Set Session Config Node's Synthesizer (TTS) section, choose that service from TTS Vendor and set language and voice.
08

Set default voices on the Application

An Application connects a Cognigy Endpoint to Voice Gateway and sets the default TTS vendor, language and voice plus the default STT vendor and language. Every call uses these until the Flow says otherwise.

VG Self-Service Portal > Applications
  1. Copy your Endpoint URLIn Cognigy, open your voice-gateway Endpoint (lesson 10) and copy its Endpoint URL.
  2. Create the ApplicationIn Applications, click Add application. Enter Application Name and pick the Account.
  3. Set both webhooksPaste the Endpoint URL into Calling Webhook and Call Status Webhook, each with method POST.
  4. Default TTSSpeech synthesis vendor: vendor, Label (if used), Language and Voice — e.g. Microsoft, en-GB, a British neural voice.
  5. Default STTSpeech recognizer vendor: vendor, Label and Language — e.g. en-GB.
  6. Add a fallback vendorActivate Use a fallback speech vendor if primary fails and pick a second TTS and/or STT vendor. Swap primary and fallback flips them.
  7. Protect against outagesActivate Perform a fallback transfer if webhook connection fails. Choose Refer (forward the call) or Dial (new outbound leg), set a Target in E.164 (e.g. +441412345678) and an optional Reason (sent as an X-Reason SIP header).
  8. Optional: call recordingUnder Call recording configuration, enable it, choose .wav or .mp3, configure an S3, Google Cloud Storage or Azure bucket, click Test, then activate Record all calls. For in-Flow control, use the Call Recording Node instead.
  9. SaveClick Save.
09

Control speech from the Flow

The Set Session Config Node changes Voice Gateway settings for the rest of the call. Put one near the top of every voice Flow, even if it only confirms the defaults; it's where hints, barge-in and timeouts live.

Flow editor > + > Extensions > VG > Set Session Config
  1. Add the NodeIn the Flow editor, click +, choose Extensions > VG, then Set Session Config. Place it directly under Start.
  2. Synthesizer (TTS)Choose TTS Vendor, TTS Language, TTS Voice and TTS Label if you labelled services. Use Custom fields for values not in the list, e.g. vendor microsoft, voice en-GB-SoniaNeural.
  3. Recognizer (STT)Choose STT Vendor and STT Language. Add STT Hints: one word or phrase per field (product names, account terms, postcodes). Use Dynamic Hints such as {{context.hints}} for runtime lists.
  4. Vendor-specific STT optionsDeepgram: Deepgram Model, Endpointing and Endpointing Time (default 10 ms), Smart Formatting. Flux: End of Turn Threshold (default 0.7) and End of Turn Timeout (default 5000 ms). Google: Google Model (default latest_short). Azure: Profanity Filter and Enable Audio Logging.
  5. Barge InEnable Barge In On Speech and/or Barge In On DTMF; set Barge In Minimum Words (2–3 stops coughs and "um" interrupting).
  6. User Input TimeoutKeep Enable User No Input Timeout on; set the mode, the timeout in milliseconds and User No Input Retries (default 5).
  7. Flow Input TimeoutFor slow LLM or API calls, enable Flow No Input Timeout with mode Speak ("One moment while I check that") or Play (an MP3/WAV URL).
  8. DTMFActivate Capture DTMF Signals; set inter-digit timeout, min/max digits and DTMF Submit Digit (e.g. #).
  9. Optional ambienceAtmosphere Sounds (background track, −50 to +50 dB) or Silence Overlay (plays during long silences).
  10. Save NodeClick Save Node.
Watch theseBarge In keeps STT listening throughout the call and can raise your speech-vendor bill. To keep Barge In behaving after transfer, put the Set Session Config Node above the Handover to Human Agent Node. Turning on Deepgram Smart Formatting re-enables punctuation even if Disable STT Punctuation is on.
The "Default" vendorIn the first Set Session Config Node, Default means "use the Application's default". In a later one it means "keep whatever the previous Node set", so you can change one setting without overwriting the vendor.

Session vs activity parameters

Set Session Config sets session parameters (rest of the call). Say, Question, Optional Question and Play Nodes can set activity parameters that apply only while that Node runs; for example, allow barge-in during a long menu but not during a legal disclaimer.

Make the agent multilingual

  1. Turn on language detectionIn Set Session Config > Recognizer, activate Recognize Language and pick up to three Alternative Language values.
  2. Branch on the detected languageAdd a Lookup Node of type CognigyScript with operator input.data.payload.speech.language_code; add Case Nodes like cy-GB, de-DE.
  3. Re-set voices per branchUnder each Case, add a Set Session Config Node with that language's TTS voice and STT language.
  4. Translate for human agentsOptionally add Set Translation Nodes (User Input Language → Flow Language) before the Handover to Human Agent Node.

Build the Additional Session Parameters JSON

The Advanced > Additional Session Parameters field takes JSON and overrides the UI settings above. Fill in the form; the JSON updates live.

When speech goes wrong

  

    
The agent is silent on a real call
  • Check the Application has a Speech synthesis vendor and voice set.
  • Check Alerts in the VG portal for expired TTS/STT credentials.
  • If the first Set Session Config uses a vendor that has no speech service in VG, there is nothing to synthesise with.

    
Voice works in the Interaction Panel but not on the phone
The Interaction Panel uses the Project's Voice Preview connection; calls use VG Speech Services. Configure both, with the same vendor, language and voice.

    
The Interaction Panel won't start a voice conversation
Your Nodes name a provider outside Google, Microsoft, AWS, Deepgram, Speechmatics and ElevenLabs, Voice Call isn't enabled for the organisation, or the browser blocked the microphone.

    
Names and policy numbers are misrecognised
  • Add STT Hints and a hints boost.
  • Collect numbers with DTMF or a Question Node of type Number.
  • Try a different STT vendor or model; Deepgram Flux and Azure Custom Speech are designed for this.

    
The agent cuts callers off, or waits too long
Tune end-of-speech detection: Deepgram Endpointing Time, Flux End of Turn Threshold/Timeout, or enable Continuous ASR (minimum 2000 ms) for callers who pause mid-sentence.

    
Long pauses while the LLM thinks
Enable TTS streaming on a supporting vendor, and set a Flow No Input Timeout with a spoken holding message or a Silence Overlay track.

    
Two services from one vendor, the wrong one is used
Give each a Label in Speech Services and reference it in the Application and the TTS Label / STT Label fields.

    
TTS costs are higher than expected
Check whether Disable TTS Audio Caching is on (every prompt is re-synthesised) and whether Barge In is keeping STT open for the whole call.
